Privacy Policy

How LinkDrop handles your data.

LinkDrop is built to move the minimum data needed to deliver links between paired devices. No advertising, no analytics, and clear control over what is stored locally or remotely.

Data we process

Local storage

  • Device credentials returned by /register_device (device ID and device secret).
  • Pair secrets, contact aliases, and “hidden” flags for the context menu.
  • Inbox cache (messages you have received, read status, opened timestamps).

This data stays on your machine inside chrome.storage.local. Clearing the extension's storage or uninstalling removes it.

Data sent to your Supabase project

  • Signed API requests carry the device ID, timestamp, and HMAC signature headers.
  • Pairing operations include short-lived pairing codes and generated pair IDs/secrets.
  • Messages include the title, URL, sender/recipient pair IDs, creation time, and optional opened time.

LinkDrop talks only to the Supabase Edge Function host listed in the manifest (host_permissions). No third-party analytics or ad endpoints are contacted.

What we do not collect

  • No browsing history beyond the specific tab you choose to send.
  • No usage analytics, tracking pixels, or advertising identifiers.
  • No passwords or account data from the pages you visit.
How data is used

Delivery only

Device credentials authenticate API calls. Pair metadata routes links to the right recipient. Message records are stored so the inbox can sync and notify you, and to mark messages as opened.

Security

  • All API requests are signed with HMAC-SHA256 using the device secret.
  • Message payloads include an HMAC signature derived from the pair secret; invalid payloads are dropped.
  • Supabase Realtime (if enabled) uses your project’s anon key; there is no shared multi-tenant backend.

Retention

Local data persists until you clear it or uninstall the extension. Data stored in your Supabase project remains until you remove it from your database; LinkDrop does not auto-expire messages by default.

Permissions

Chrome permissions used

  • contextMenus: to add “Send current page” and contact shortcuts.
  • tabs: to read the current tab title and URL when you choose to send.
  • notifications: to show incoming link alerts you can click.
  • storage: to store device credentials, pairs, aliases, and inbox cache locally.
  • alarms: to schedule periodic inbox polling when realtime is unavailable.

Host permissions

The extension calls only the Supabase Edge Functions host configured in manifest.json and src/config.js. Update these to point at your own project before publishing.

Sharing

LinkDrop does not sell or share data with third parties. Data flows only between the extension and your Supabase project to complete link delivery.

Your controls

Manage contacts & cache

Remove contacts from the popup to revoke them. Delete messages from the inbox or mark all as read. Hidden contacts remain local only.

Clear local data

Use the “Clear cache” action in the extension or remove/uninstall the extension to erase local storage. To remove server-side data, delete records from your Supabase database.

Changes

Updates to this policy will be versioned in the repository. Review release notes when upgrading.
